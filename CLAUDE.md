# CLAUDE.md

Этот файл содержит рекомендации для AI-ассистентов и агентов при работе с кодом в этом репозитории.

> **Примечание**: Инструкции совместимы с различными AI-инструментами (Claude Code, GitHub Copilot,
> Cursor, Aider и другие).

## Рекомендации по коммуникации

- **Всегда отвечай на русском языке** при работе в этом репозитории
- Избегай очевидных комментариев в коде (например, "// Создаем переменную", "// Вызываем функцию")
- Пиши только осмысленные комментарии, которые объясняют "почему", а не "что"

## CORE POLICY

Ниже — **единый источник правды** по юнит‑тестам и Git‑истории. Эти правила имеют **наивысший
приоритет**.

### Git Policy (MUST) — Always Fixup, base branch = develop

- **Новые логические изменения** оформляй обычными атомарными коммитами (см. `make_commit`).
- **После ревью**: **ВСЕГДА** делай правки через fixup и autosquash:
    1) `git commit --fixup <hash>` (к соответствующему коммиту)
    2) `git fetch origin develop && git rebase -i --autosquash origin/develop`
    3) итог: в ветке **не остаётся** коммитов "review fixes", история — **финальная**, каждый коммит
       отражает итоговый код своего шага.
- **Запрещено**: отдельный коммит "правки после ревью".

### History rewrite (MUST)

- Операции переписывания истории (`rebase`, `reset`, `recommit`) — **опасные**. Их можно делать
  только по правилам и **при необходимости** запрашивать явное подтверждение пользователя (это
  единственное допустимое "STOP/confirm").

## Использование саб-агентов

При выполнении задач **настоятельно рекомендуется использовать специализированных саб-агентов**,
если они подходят под задачу:

- **kotlin-code-quality-enforcer**: Используй для проверки качества кода, запуска lint, detekt,
  исправления стиля кода. Запускай проактивно перед коммитом или мерджем.
- **unit-test-fixer**: Используй для исправления падающих тестов, анализа ошибок в тестах, проверки
  тестов после изменений кода.
- **feature-readme-generator**: Используй для генерации README документации для фич.

Саб-агенты помогают автоматизировать рутинные задачи и гарантируют соблюдение стандартов проекта.

## Стиль кода и качество

### Стиль Kotlin

- **Руководство по стилю**: Официальный стиль кода Kotlin с отступом в 4 пробела
- **Длина строки**: Максимум 135 символов
- **Порядок импортов**: `*, java.**, javax.**, kotlin.**, ^` (обеспечивается Detekt)
- **Конвенции именования**:
    - PascalCase для классов и объектов
    - camelCase для функций, переменных и свойств
- **Expression Body синтаксис**: Используй expression body (`=`) для функций, которые возвращают
  единственное выражение
  ```kotlin
  // ✅ Правильно
  fun createFile(name: String): File =
      File(directory, name)

  // ❌ Неправильно
  fun createFile(name: String): File {
      return File(directory, name)
  }
  ```
- **Fully Qualified Names (FQN)**: НЕ используй FQN в коде. Всегда добавляй импорты вместо полных
  имен классов
  ```kotlin
  // ✅ Правильно
  import ru.vk.store.lib.logging.api.ExportLogsResult

  val result = when (value) {
      is ExportLogsResult.Success -> value.uri
      is ExportLogsResult.Error -> null
  }

  // ❌ Неправильно
  val result = when (value) {
      is ru.vk.store.lib.logging.api.ExportLogsResult.Success -> value.uri
      is ru.vk.store.lib.logging.api.ExportLogsResult.Error -> null
  }
  ```
